# 类小红书 ERP 全站外观改造设计

## 目标

将当前 Flask ERP Demo 的全站视觉统一为轻量、留白充足、卡片化的内容应用风格，借鉴用户提供的小红书参考图中的信息密度、侧边导航、顶部操作区和多卡片节奏，同时保留 ERP 页面所需的表格可读性、表单效率和业务状态辨识度。

本次只改变模板结构、共享样式和必要的前端展示辅助，不改变 Flask 路由、数据库字段、业务流程、订单状态或 AI 助手接口。

## 现状与范围

项目使用 Flask、Jinja2、Bootstrap 5 和单个全局 CSS 文件。所有页面继承 `templates/base.html`，现有业务页面分为：

- 工作台首页：`templates/dashboard.html`
- AI 助手：`templates/assistant.html`
- 基础资料：商品、客户、供应商列表和表单
- 采购与销售：订单列表、创建表单和详情页
- 财务：应收账款和应付账款列表
- 系统日志：数据库操作日志和 API 调用日志

改造覆盖以上所有页面及桌面/窄屏布局。后端路由和已有表单 action 保持不变。

## 设计原则

1. **内容优先**：借鉴参考图的卡片化和留白，但不把订单、日志或表单强行做成瀑布流；ERP 数据仍以易扫描、易操作为首要目标。
2. **共享一致**：导航、顶部区域、页面标题区、卡片、按钮、表格、表单、状态标签和空状态只定义一套视觉语言。
3. **状态清晰**：主操作使用珊瑚红；成功/已完成使用柔和绿色；错误使用柔和红色；AI/信息提示使用浅紫或浅蓝，颜色不作为唯一状态依据，文字标签必须保留。
4. **不制造假功能**：不新增没有后端支持的全局搜索、筛选或通知交互。顶部区域只提供现有页面和 AI 助手可以实际到达的快捷入口。
5. **渐进兼容**：继续使用 Bootstrap 5 的栅格、表单和响应式工具类；新增样式集中在 `static/css/style.css`，避免引入新的前端框架或图标依赖。

## 视觉系统

### 色彩

- 页面背景：暖白/浅灰，目标值约为 `#f7f7f5`。
- 表面：白色卡片 `#ffffff`。
- 主文字：深灰 `#252525`；辅助文字：中性灰 `#7d7d7d`。
- 主操作/当前导航：珊瑚红，目标值约为 `#ff385c`。
- 成功：低饱和绿色；警告：低饱和橙色；信息/AI：低饱和蓝紫色。
- 边框：极浅灰；阴影使用低透明度，避免当前深色侧栏的厚重感。

### 形状与间距

- 页面和卡片使用中等圆角，表单输入与按钮使用略小圆角。
- 主内容区域保持较宽的左右留白，桌面端使用 24–32px 页面内边距。
- 卡片之间使用统一的 Bootstrap gap，不让边框和阴影堆叠。
- 统一可聚焦状态，键盘操作时保留可见的珊瑚红 focus ring。

### 字体与层级

- 继续使用系统中文无衬线字体栈，不额外下载字体。
- 页面标题突出但不过大；辅助说明使用较小的灰色文本。
- 金额、库存和数量使用更强字重；表格字段保持紧凑，避免大面积粗体。

## 共享壳层

### 桌面端

`templates/base.html` 调整为浅色左侧导航 + 主内容区结构：

- 顶部品牌区域保留 `ERP Demo`，采用简洁文字标识，不复制小红书 logo。
- 导航分为工作台、智能助手、基础资料、采购管理、库存管理、销售管理、财务管理和系统管理。
- 当前导航项根据 Flask 当前 endpoint 自动高亮；禁用占位功能保持不可操作并使用弱化样式。
- 主内容顶部增加轻量工具栏，提供页面上下文/返回关系以及现有的 AI 助手和新建业务快捷入口。
- 主内容区使用 `page-shell`、`page-header`、`surface-card` 等明确的语义类，减少模板中重复的 Bootstrap 阴影组合。

### 窄屏端

- 左侧导航不占用固定宽度，改为顶部可收起的导航区域。
- 主内容横向不溢出；表格通过 `.table-responsive` 保留横向滚动。
- 页面标题区在窄屏下允许主操作按钮换行，按钮不被压缩到不可读。
- 订单详情的多列摘要在窄屏下依次堆叠。

## 页面级设计

### 工作台首页

- 以“工作台/当前 ERP 数据概况”为页面标题区。
- 使用四张小型运营指标卡表达商品数量、库存、待入库采购和待出库销售。
- 使用三张较宽的财务/销售卡表达未收应收、未付应付和已完成销售总额。
- 每张卡保留现有服务端计算值，增加轻量图标或色彩标识，但不添加虚构趋势数据、图表或活动流。

### 基础资料列表与表单

- 商品、供应商、客户列表统一为标题区 + 主操作 + `surface-card` 表格。
- 表格表头淡化，核心字段（商品名、SKU、库存、金额、名称）保持清晰对齐；编辑动作使用紧凑的次级按钮。
- 新增/编辑页面使用窄宽度编辑卡；商品价格字段在桌面端两列排列，窄屏端堆叠。
- 现有错误列表和空状态改为统一的反馈组件，但保留原有错误文本。

### 采购/销售订单

- 列表页使用状态 pill、对象名称、订单金额和创建时间的清晰列结构；主操作位于标题区。
- 新建页分为“供应商/客户信息”“商品明细”“操作栏”三组卡片；继续使用现有 checkbox、数量和单价字段。
- 详情页先展示订单号、关联对象、创建时间和状态摘要，再展示商品明细表。
- 订单履约后的应收/应付和库存流水分别位于独立卡片；确认提交、入库、出库按钮沿用现有 POST action，只改变外观和布局。

### 应收/应付

- 页面标题区保留当前业务说明。
- 表格突出金额、关联订单、状态和可执行的收款/付款操作。
- 未结算操作使用珊瑚红主按钮；已完成状态使用绿色弱标签和文本，不再占用强按钮视觉权重。

### 日志

- 数据库日志和 API 日志保持表格形态，统一标题区的日志互链按钮。
- 成功/失败使用带文字的状态 pill；耗时、HTTP 状态和 token 数量使用辅助层级。
- JSON 详情和错误内容不改变数据，只通过字体、换行和响应式横向滚动降低视觉噪音。

### AI 助手

- 上部保留页面说明和 DeepSeek Agent 标识，改为柔和信息标签。
- 示例问题使用 chips，保留现有点击填充行为。
- 对话区为白色圆角消息面板，用户消息与助手消息使用不同浅色表面，错误仍然使用错误色。
- 订单确认预览使用独立高亮卡片，确认/取消按钮保留现有 `confirmation_token` 流程。
- 输入区使用更大的圆角输入框和主发送按钮，保留现有表单提交和 AJAX 行为。

## 模板与样式边界

预期修改范围：

- `templates/base.html`：共享壳层、导航分组、当前 endpoint 高亮、顶部工具区和语义类。
- `templates/dashboard.html`：首页卡片层级和布局。
- `templates/assistant.html`：AI 页面展示结构。
- `templates/products/*.html`、`templates/customers/*.html`、`templates/suppliers/*.html`：基础资料列表/表单外观。
- `templates/purchase_orders/*.html`、`templates/sales_orders/*.html`：订单列表/表单/详情外观。
- `templates/receivables/list.html`、`templates/payables/list.html`：结算表格外观。
- `templates/logs/*.html`：日志表格外观。
- `static/css/style.css`：全局 design tokens、壳层、卡片、表格、表单、状态和响应式规则。
- `static/js/assistant.js`：仅在新 DOM 结构需要时调整选择器或反馈卡片 class，不改变请求地址、请求体和确认流程。

不修改：

- `app.py`、`models.py`、`routes/`、`services/`、`agent/` 中的业务逻辑和数据接口。
- 数据库 schema、表单字段 name、POST action、AI API 路径和订单履约流程。
- 现有依赖清单，除非实际验证发现 Bootstrap 资源本身不可用。

## 验收标准

1. 所有现有页面都使用同一套浅色壳层、导航高亮、页面标题区、卡片和状态标签。
2. 每个现有 URL 仍能访问；所有新增、编辑、提交、收款、付款、入库、出库和 AI 确认动作的请求地址与数据保持不变。
3. 首页的现有七个指标仍显示正确服务端值，且页面不依赖硬编码演示数据。
4. 表单错误、空列表、日志错误和 AI 错误反馈仍能显示，内容不丢失。
5. 桌面端导航和多列卡片布局稳定；窄屏端主内容不发生不可接受的横向溢出，表格可横向滚动。
6. 现有 pytest 测试全部通过，并新增至少一项模板回归检查，验证关键页面包含新的共享壳层标记和 Dashboard 可访问性。
7. 通过浏览器或本地渲染检查：首页、一个列表页、一个表单页、一个订单详情页和 AI 助手页都没有明显重叠、截断或不可读文本。

## 明确不做

- 不复制小红书品牌 logo、品牌名称或受保护的页面素材。
- 不把 ERP 业务记录伪装成社区帖子，也不新增点赞、收藏、评论、关注等社交功能。
- 不新增全局检索、数据图表、通知中心或移动端原生交互，除非后续另行提出需求。
- 不重构后端路由和数据模型。
