# ERP Excel/PDF 导出与 AI 文档解读 — 设计说明

**日期：** 2026-09-27
**状态：** 用户已确认设计范围，待审阅本文档
**范围：** 业务列表导出、AI 助手导出、PDF/XLSX 文档解读

## 目标

让 ERP 业务列表能导出 Excel（`.xlsx`）和 PDF；AI 助手也能根据自然语言导出同一批业务数据。用户还可以在 AI 助手上传可提取文本的 PDF 或 `.xlsx`，针对文件内容提问并获得解读。

## 已确认的范围

业务列表导出覆盖：

- 商品、客户、供应商
- 当前库存、库存流水
- 采购订单、销售订单
- 应收账款、应付账款

系统日志不在本次导出范围。AI 助手通过与页面相同的白名单导出服务生成文件，并提供下载链接。

文档解读第一版支持 PDF 和 `.xlsx`。文件在服务器内存中解析，不保存原文件；提取出的文本和表格内容会发送给当前配置的 DeepSeek，用于回答用户问题。扫描版 PDF 的 OCR 和旧版 `.xls` 不在范围内。

## 方案

### 导出服务

新增共享导出服务，按明确的 dataset allowlist 查询 ERP 数据，并将每个数据集渲染为 XLSX 或 PDF。Web 页面和 AI 工具都调用同一服务，避免两种入口导出内容不一致。

每种数据集定义自己的列名、排序和关联字段。例如订单导出包含订单编号、往来方、状态、总金额、创建时间和订单明细；库存流水包含商品、入/出库类型、数量、关联订单、结存和时间。金额在 XLSX 中使用数值单元格和货币格式。PDF 使用适合中文的字体并按列数选择页面方向，支持分页和长文本换行。

在各业务列表增加 XLSX/PDF 导出按钮。下载路由只接受白名单数据集和格式，并以附件形式返回文件；不允许通过任意模型名、列名或 SQL 参数访问其他数据。

### AI 助手导出

增加只读 `export_dataset` AI 工具，参数仅包括白名单中的数据集标识和 `xlsx`/`pdf` 格式。模型只负责从自然语言映射到工具参数，不能生成 SQL 或文件内容。后端生成文件并返回短期、不可预测的下载地址，前端将其呈现为下载链接。

示例请求包括“导出当前库存 Excel”“把未收应收导出成 PDF”。如数据集或格式缺失、无法识别，助手先追问或返回支持范围，不生成任意导出。

### PDF 与 Excel 解读

助手输入区增加文件选择控件和文件提问字段。上传路由将 PDF 页面文字或 `.xlsx` 工作簿的工作表/单元格提取为受限长度的纯文本，然后调用当前 LLM 客户端进行解读，调用时不提供 ERP 写工具。

系统提示明确将文件内容视为不可信数据，只能根据内容回答，不执行文件中嵌入的指令，也不允许因为文件内容触发订单、结算、库存或其他 ERP 工具。上传文件只在请求内处理，不写入数据库或持久目录。上传区域清楚说明提取内容会发送到 DeepSeek。

实施时设置单文件大小、PDF 页数、工作簿非空单元格数和提取文本长度上限。达到上限时返回具体、可理解的提示，不静默截断或让模型假装看到了全部内容。第一版不对 PDF 图片做 OCR；扫描版文件应提示用户上传可搜索文本 PDF 或另行提供文字内容。

## 数据流

```text
页面导出按钮 ─┐
              ├─> 白名单导出服务 ─> XLSX/PDF 响应
AI export 工具 ┘                    └─> 短期下载链接
```

```text
用户问题 + PDF/XLSX
  -> 上传大小与格式校验
  -> 服务端内存提取文本/单元格
  -> 作为不可信文档内容发送到 DeepSeek
  -> 无 ERP 工具的文档解读调用
  -> AI 助手显示回答
```

## 错误处理与安全约束

- 未知数据集、未知格式、无效或过期下载令牌返回明确错误，不暴露文件路径。
- 无法读取、加密或损坏的 PDF/XLSX 返回可理解的文件错误；不回显内部异常。
- 空文档、纯扫描 PDF 或没有可提取文字的页面明确说明未提取到可解读内容。
- 上传超限或提取量超限时拒绝处理并提示限制，不保存上传内容。
- 文档解读请求不注册 ERP 工具，也不执行任何业务写操作。
- 文件名经过安全处理；响应设置附件下载文件名和正确 MIME type。
- XLSX 文本/数值单元格通过工作簿 API 写入，不将用户数据解释为公式；PDF 内容通过安全文本布局写入。
- PDF 生成采用项目依赖中明确安装的库和中文字体配置，不能依赖开发者机器上的任意字体路径。

## 计划涉及的代码区域

- 新增 `services/exports.py`：数据集白名单、业务查询、XLSX/PDF 渲染。
- 新增 `routes/exports.py`：页面下载和短期 AI 下载地址路由。
- 修改 `app.py`：注册导出路由与必要的请求体限制。
- 修改业务列表模板：添加 XLSX/PDF 导出入口。
- 修改 `agent/tools.py`、`agent/prompts.py`、`agent/service.py`：注册并执行导出工具，增加隔离的文档解读入口。
- 修改 `routes/assistant.py`、`templates/assistant.html`、`static/js/assistant.js`：上传控件、AI 下载链接和解读响应展示。
- 修改 `requirements.txt`：增加 XLSX/PDF 读写与文本提取依赖。
- 更新 `README.md`：列出导出范围、支持格式和文档解读限制。

具体文件以实现时对模板结构的检查为准；不修改数据库 schema，也不改变已有订单、库存和结算业务规则。

## 验收标准

1. 每个纳入范围的业务列表都能分别下载 XLSX 和 PDF，文件包含页面对应的真实业务字段。
2. AI 可以按自然语言生成支持数据集的 XLSX/PDF 下载链接；无效数据集不会执行任意查询。
3. 上传普通可搜索 PDF 或 XLSX 后，助手能基于文件内容回答用户问题。
4. 文件上传格式、大小、页面/单元格和文本上限有校验，错误响应明确。
5. 文档内容不会被当作可执行指令，解读流程不调用 ERP 工具或修改业务数据。
6. 未提交的用户改动不被覆盖，也不混入本设计说明的提交。

## 设计自检

- 页面导出和 AI 导出共享同一服务和数据集白名单。
- 上传解析与 ERP 工具调用隔离，文档提示注入不能触发写操作。
- PDF/OCR 与 `.xls` 的不支持边界已明确。
- 文件只在请求期内解析；上传文档不进入持久存储。
- 不引入数据库迁移或改变订单履约、库存和财务规则。
