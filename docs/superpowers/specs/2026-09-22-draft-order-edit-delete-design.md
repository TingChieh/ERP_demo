# 草稿订单修改与删除设计

日期：2026-09-22

## 目标

为采购订单和销售订单增加草稿状态下的修改、删除能力，同时保持已经提交、履约和财务流程不变。

本阶段只允许操作 `draft` 订单：

- 采购订单：`draft` 可编辑、可删除；`pending_receipt` 和 `completed` 禁止编辑、删除。
- 销售订单：`draft` 可编辑、可删除；`pending_shipment` 和 `completed` 禁止编辑、删除。

订单号和创建时间始终不可修改。

## 用户交互

采购订单详情页和销售订单详情页在草稿状态显示：

- 编辑草稿
- 删除草稿

非草稿状态不显示这两个操作按钮。

编辑页面复用现有新建订单表单布局和校验：

- 采购订单编辑供应商、商品明细、数量、采购单价。
- 销售订单编辑客户、商品明细、数量、销售单价。
- 页面载入时展示当前订单数据。
- 保存成功后返回订单详情页。
- 校验失败时保留用户输入并展示错误信息。

删除按钮需要确认提示。确认后删除订单及其明细并返回列表；取消不产生变化。

## 后端接口

采购订单新增：

- `GET /purchase-orders/<order_id>/edit`
- `POST /purchase-orders/<order_id>/edit`
- `POST /purchase-orders/<order_id>/delete`

销售订单新增：

- `GET /sales-orders/<order_id>/edit`
- `POST /sales-orders/<order_id>/edit`
- `POST /sales-orders/<order_id>/delete`

所有接口在服务端重新校验订单状态，不能仅依赖页面是否显示按钮来保证安全。

## 数据处理

编辑保存使用一个数据库事务：

1. 读取订单并确认状态为 `draft`。
2. 校验供应商或客户存在。
3. 校验至少一条商品明细、商品存在、商品不重复。
4. 校验数量为正整数，单价为非负有限金额。
5. 更新供应商或客户。
6. 删除旧订单明细并写入新明细。
7. 根据数量和单价重新计算总金额。
8. 保留订单号、创建时间和 `draft` 状态。

删除只允许 `draft` 订单，并通过订单明细关系的级联删除删除 `PurchaseOrderItem` 或 `SalesOrderItem`。

编辑和删除都不能修改：

- `Product.stock`
- `InventoryTransaction`
- `AccountPayable`
- `AccountReceivable`

业务服务层提供采购、销售草稿的更新和删除函数，路由层负责页面展示、表单读取和错误回显。更新函数复用现有订单行标准化与金额计算规则，并记录数据库操作日志。

## 错误处理

- 非草稿编辑或删除返回 HTTP 400，并展示“只有草稿状态的订单可以编辑/删除”。
- 商品、供应商、客户、数量、单价或明细格式错误时，不提交任何数据库变化。
- 数据库事务失败时回滚全部明细和订单字段变更，并保留原订单。
- 删除成功后不产生库存或财务记录。

## 测试

采购和销售订单测试分别覆盖：

- 草稿详情页显示编辑、删除操作。
- 草稿编辑供应商或客户、商品、数量、单价。
- 编辑后总金额重新计算。
- 编辑失败时数据库保持不变。
- 草稿删除订单及其明细。
- 删除不改变库存、库存流水、应收或应付。
- 非草稿订单不能编辑或删除。
- 现有创建、提交、入库、出库和财务测试继续通过。

## 非目标

本阶段不实现：

- 修改订单号或创建时间。
- 编辑已提交、待入库、待出库或已完成订单。
- 恢复已删除草稿。
- 草稿版本历史或审计回滚。
- 自动提交、自动入库或自动出库。
