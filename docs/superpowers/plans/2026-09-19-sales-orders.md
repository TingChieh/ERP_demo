# Sales Orders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add draft sales-order creation, listing, detail viewing, and draft submission to the pending-shipment state without implementing shipment or receivables.

**Architecture:** Add a server-rendered `sales_orders` Blueprint mirroring the readable purchase-order flow. The create route validates customer and line data, calculates the total with Decimal, and commits the sales order plus all items together; it deliberately does not inspect or mutate Product.stock because inventory fulfillment belongs to the later shipment workflow.

**Tech Stack:** Flask, Flask-SQLAlchemy, SQLAlchemy, SQLite, Jinja2, Bootstrap 5, pytest.

## Global Constraints

- Do not implement sales shipment, stock decrease, outbound inventory transactions, receivables, collection, or supplier payment.
- Sales orders are created as `draft` and can be submitted to `pending_shipment`.
- Creating or submitting a sales order does not require sufficient stock and does not reserve stock.
- Sales order numbers are generated by the server and are unique.
- total_amount is recalculated server-side from quantity multiplied by unit_price using Decimal/Numeric.
- SalesOrderItem.unit_price stores the transaction price snapshot and does not dynamically read Product.sale_price.
- Do not implement sales-order editing in this phase.
