# Purchase Orders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add draft purchase-order creation, listing, detail viewing, and draft submission to the pending-receipt state without implementing receipt or finance behavior.

**Architecture:** Add one server-rendered `purchase_orders` Blueprint with list, create, detail, and submit routes. The create route validates all submitted lines, calculates the total from Decimal values, and commits the order plus every item in one SQLAlchemy transaction; it never writes Product.stock or any inventory/finance table.

**Tech Stack:** Flask, Flask-SQLAlchemy, SQLAlchemy, SQLite, Jinja2, Bootstrap 5, pytest.

## Global Constraints

- Do not implement purchase receipt, inventory increase, inventory transactions, payables, payments, or sales.
- Purchase orders are created as `draft` and can be submitted to `pending_receipt`.
- Only draft orders can be submitted; pending-receipt orders cannot be submitted again.
- Order numbers are generated by the server and are unique.
- total_amount is always recalculated server-side from quantity multiplied by unit_price using Decimal/Numeric.
- Creating or submitting a purchase order never changes Product.stock.
- Do not implement purchase-order editing in this phase.
